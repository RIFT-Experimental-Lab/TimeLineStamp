# Запуск на выделенном Android-телефоне

Проверенная модель телефона — Xiaomi 11 Lite 5G NE (`2109119DG`, `lisa`). Эти шаги работают на штатном Android без root. Текущий комплект не меняет прошивку телефона.

## Перенести проект

1. Установите [Termux](https://f-droid.org/en/packages/com.termux/) и [Termux:Boot](https://f-droid.org/en/packages/com.termux.boot/) из **одного источника**. Откройте Termux:Boot хотя бы один раз после установки. Не смешивайте APK из F-Droid и GitHub: их подписи различаются.
2. На Mac в папке `repository/` выполните `./android/package.command`. Архив появится в соседней локальной папке `../local/packages/TimeLineStamp-android.tar.gz` без базы измерений и секретов. Рядом будет файл `.sha256`; проверить архив на Mac можно командой `shasum -a 256 -c ../local/packages/TimeLineStamp-android.tar.gz.sha256`.
3. Перенесите архив в папку `Download` телефона по USB или командой `adb push ../local/packages/TimeLineStamp-android.tar.gz /sdcard/Download/`.
4. В Termux выполните:

```sh
termux-setup-storage
pkg update
pkg install python
mkdir -p ~/TimeLineStamp
tar -xzf ~/storage/downloads/TimeLineStamp-android.tar.gz -C ~/TimeLineStamp
sh ~/TimeLineStamp/android/install-termux.sh
```

Разрешите Termux доступ к файлам, когда Android спросит. Установщик проверит Python, исходные скрипты и доступ к общей папке. После установки сборщик запускается сам после следующей перезагрузки. До настройки GitHub он только собирает данные локально. Если папка проекта будет другой, измените `TIMELINESTAMP_PROJECT_DIR` в `~/.config/timelinestamp/config`.

## Проверить перед суточным сбором

В Termux:

```sh
python ~/TimeLineStamp/test_now.py
~/.termux/boot/90-timelinestamp
```

Первой строкой теста должно быть число. Вторую команду оставьте работающей и заблокируйте экран. Держите телефон на зарядке, разрешите Termux работу без ограничений батареи и проверьте сеть через Wi-Fi и SIM-карту. На новой прошивке сначала проведите хотя бы одни полные сутки наблюдения: прошивка сама по себе не гарантирует непрерывный процесс.

Проверить состояние и последние сообщения:

```sh
python ~/TimeLineStamp/timelinestamp.py --status
tail -n 30 ~/.local/state/timelinestamp/collector.log
tail -n 30 ~/.local/state/timelinestamp/launcher.log
```

## Проверить расширенный набор v2 с самого телефона

После установки обновлённого архива выполните в Termux:

```sh
python ~/TimeLineStamp/probe_v2_sources.py --require-termux --output ~/.local/state/timelinestamp/probe-v2.json
python ~/TimeLineStamp/probe_v2_sources.py --list-requests
python ~/TimeLineStamp/v2_toggle.py list
```

Первая команда делает реальные HTTPS-запросы с телефона ко всем 34 закреплённым рядам и зонам; вторая печатает точный список URL с актуальными датами без повторной загрузки. Для текущих источников проверка смотрит свежий снимок; для исторических — данные за текущие сутки; для Wikimedia — полные предыдущие сутки. `ok` означает, что ответ получен и разобран, `stale` — что последнее измерение старше восьми часов, `delayed` — что ещё нет всех 24 часовых значений Wikimedia, `failed` — сетевую ошибку, пустой или неожиданный ответ. Команда выводит результаты по каждому ID и сохраняет HTTP-код, размер, время запроса и хеш ответа в локальный JSON. Сам факт `HTTP 200` без полезных данных успехом не считается. Выходной код `1` означает, что хотя бы одна позиция не готова.

Запросы построены из `v2_sources.py`; точные ID, станции и URL также сведены в локальном документе `v2-ready-source-set.md`. Основные адреса: `geofon.gfz.de/fdsnws`, `service-nrt.geonet.org.nz/fdsnws`, `imag-data.bgs.ac.uk/GIN_V1/hapi`, `api.tidesandcurrents.noaa.gov/api/prod`, `ndbc.noaa.gov/data/realtime2`, `api.waterdata.usgs.gov/ogcapi/v1`, `api.weather.gc.ca/collections/hydrometric-realtime`, `environment.data.gov.uk/flood-monitoring`, `pegelonline.wsv.de/webservices/rest-api/v2`, `opensky-network.org/api/states/all`, `wikimedia.org/api/rest_v1`, `planet.openstreetmap.org/replication/minute`. Это именно запросы из сети телефона; запуск такого же теста на Mac не устанавливает доступность на Android.

Для быстрого исключения проблемного ряда или всего поставщика:

```sh
python ~/TimeLineStamp/v2_toggle.py disable im_sit
python ~/TimeLineStamp/v2_toggle.py disable-group opensky
python ~/TimeLineStamp/v2_toggle.py enable im_sit
python ~/TimeLineStamp/v2_toggle.py list
```

ID и группы перечисляет `list`. Настройки живут только в `~/.config/timelinestamp/v2-sources.json`; при обновлении архива не заменяются. Изменение применяется к ещё не закрытым суткам, а закрытые записи остаются неизменными. Для теневого сбора без изменения суточного числа выполните `python ~/TimeLineStamp/v2_toggle.py shadow YYYY-MM-DD`, указав сегодняшнюю или будущую дату UTC. После проверки полноты назначьте **будущую** дату первого полного дня v2 UTC командой `python ~/TimeLineStamp/v2_toggle.py activate YYYY-MM-DD`. Сборщик читает настройки автоматически в каждом цикле; перезапуск не требуется. До назначенной даты продолжает работать v1. Новый день v2 закрывается через 48 часов 15 минут после его окончания, чтобы дождаться запаздывающих часовых данных; публикация страницы происходит после закрытия.

После отключения групп команда `python ~/TimeLineStamp/probe_v2_sources.py --require-termux --enabled-only` проверяет только включённые источники. Полную проверку всех 34 можно по-прежнему запускать без `--enabled-only`.

Сборщик работает без открытого веб-порта, хранит измерения в `~/TimeLineStamp/data/timelinestamp.sqlite3` и запускается повторно, если завершился процесс Python. Termux:Boot запускает его после перезагрузки; `termux-wake-lock` вызывается автоматически. Вторая копия сборщика с той же базой не запустится. Если Android завершит само приложение Termux, его внутренний перезапуск тоже остановится; после следующей ожидаемой суточной фиксации страница покажет задержку публикации. При отключении питания или сети возможны пропуски; история уже зафиксированных суток не меняется.

## Управление с Mac по SSH в локальной сети

Телефон и Mac должны быть в одной локальной сети Wi-Fi. Узнайте IPv4 телефона в настройках Wi-Fi Android и закрепите этот адрес за телефоном в настройках DHCP роутера. Скрипт ниже принимает только частный адрес `10.x.x.x`, `172.16–31.x.x` или `192.168.x.x`; SSH будет слушать **только этот адрес** на порту `8022`. Переадресацию порта на роутере не включайте.

На Mac проверьте, есть ли публичный ключ: `ls ~/.ssh/id_ed25519.pub`. Если его нет, создайте пару командой `ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519`; сохраните приватный ключ только на Mac. Скопируйте **только публичный** ключ на телефон, например:

```sh
adb push ~/.ssh/id_ed25519.pub /sdcard/Download/timelinestamp-mac.pub
```

В Termux выполните, заменив адрес на IPv4 телефона:

```sh
sh ~/TimeLineStamp/android/enable-ssh.sh ~/storage/downloads/timelinestamp-mac.pub 192.168.1.42
```

Скрипт установит OpenSSH, добавит ключ в `~/.ssh/authorized_keys`, выключит вход по паролю и выведет пользователя Termux и отпечаток ключа **сервера**. Запишите их. Затем перезагрузите телефон: Termux:Boot запустит SSH вместе со сборщиком. Для проверки без перезагрузки запустите `~/.termux/boot/90-timelinestamp`, если он ещё не работает. Повторный запуск загрузочного скрипта создаст вторую оболочку, поэтому для штатной проверки используйте перезагрузку.

С Mac подключитесь, подставив имя пользователя, адрес и путь к приватному ключу:

```sh
ssh -p 8022 -i ~/.ssh/id_ed25519 USER@192.168.1.42
```

При первом входе сверьте показанный Mac отпечаток ключа сервера с тем, который вывел телефон. Если роутер изолирует Wi-Fi-клиентов друг от друга, подключение не получится до отключения этой опции. Если адрес телефона изменится, заново выполните `enable-ssh.sh` с новым адресом и перезагрузите телефон. На Mac можно подключаться также с помощью SFTP: `sftp -P 8022 -i ~/.ssh/id_ed25519 USER@192.168.1.42`.

После входа по SSH доступны обычные команды Termux:

```sh
python ~/TimeLineStamp/timelinestamp.py --status --backup-dir ~/storage/shared/TimeLineStamp-backups
tail -n 50 ~/.local/state/timelinestamp/collector.log
tail -n 50 ~/.local/state/timelinestamp/launcher.log
tail -n 50 ~/.local/state/timelinestamp/ssh-supervisor.log
python ~/TimeLineStamp/timelinestamp.py --restart
```

Команда `--restart` просит сборщик завершить текущий цикл; загрузочный скрипт запускает его снова через 60 секунд. Если SSH не отвечает, сначала проверьте адрес Wi-Fi, питание и работу Termux на самом телефоне. SSH не открывает интерфейс измерений в локальной сети и не связан с будущей страницей GitHub Pages.

## Хранение минимум за год

Все принятые записи NIST, NQSN и NOAA сохраняются в SQLite вместе с исходными ответами маяков и строками NOAA; программа **не удаляет старые измерения**. После первой суточной фиксации и затем после каждой следующей создаётся полная сжатая копия базы в `~/storage/shared/TimeLineStamp-backups`. Хранятся две последние копии, каждая содержит всю историю с первого дня. Копия создаётся через SQLite Backup API и проверяется до замены старой. Папка копий находится вне закрытого каталога Termux, поэтому её можно перенести на Mac по USB. Раз в месяц стоит делать такую внешнюю копию: две копии на том же телефоне не защитят от потери устройства.

По измеренным сегодня размерам ответов пробный день занял около **5,3 МиБ** в SQLite; это примерно **1,9 ГиБ за год** при неизменном формате источников. Даже с двумя полными копиями ожидаемый объём существенно меньше 64 ГБ, но фактический свободный объём и рост базы нужно проверять. Команда ниже показывает количество записей, старейшую и новейшую запись, размер базы, свободное место и копии:

```sh
python ~/TimeLineStamp/timelinestamp.py --status --backup-dir ~/storage/shared/TimeLineStamp-backups
```

При восстановлении сначала остановите сборщик и сохраните текущую базу отдельно. Затем распакуйте выбранную `.sqlite3.gz` во временный файл, проверьте его через `PRAGMA integrity_check` и только после этого замените рабочую базу. Не заменяйте базу во время работы сборщика.

## Подключить публикацию позже

После создания репозитория и страницы по [GITHUB_PAGES.md](GITHUB_PAGES.md) создайте на GitHub fine-grained personal access token с правом **Contents: Read and write** только для этого репозитория. Токен хранится только в Termux:

```sh
umask 077
cat > ~/.config/timelinestamp/github-token
```

Вставьте токен и нажмите `Ctrl+D`. Проверьте `chmod 600 ~/.config/timelinestamp/github-token`. В `~/.config/timelinestamp/config` задайте `TIMELINESTAMP_REPO="OWNER/REPO"`, затем перезагрузите телефон. Не добавляйте токен в проект, Git или JavaScript страницы.

Сервер отправляет только последнюю закрытую суточную запись и до 30 записей истории. Текущие счётчики, сырые ответы источников и SQLite остаются на сервере. `docs/data/status.json` обновляется только после новой суточной фиксации; при перезапуске уже опубликованный день повторно не отправляется. При ошибке публикации сбор продолжается, повторная попытка выполняется через пять минут. Страница помечает публикацию как задержанную, если очередная запись не появилась примерно через три часа после ожидаемого времени.
