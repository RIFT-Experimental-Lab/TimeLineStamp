# Timelinestamp

Экспериментальный измеритель цифрового отпечатка физических событий. Первая версия собирает квантовые пульсы NIST и NQSN, а также минутные измерения солнечного ветра NOAA. Один коэффициент фиксируется раз в сутки и показывается до следующей фиксации.

Проект не является детектором альтернативных реальностей. Различие отпечатков показывает различие полученных данных, а не его причину.

Связь с лабораторией: [rift.research@outlook.com](mailto:rift.research@outlook.com).

## Запуск

Нужен Python 3.9 или новее. Сторонние Python-пакеты не требуются.

### Разовое тестовое измерение на macOS

В терминале выполните из папки проекта:

```sh
./test_now.command
```

Скрипт сразу запрашивает общий свежий пульс NIST и NQSN, последние пригодные измерения NOAA, вычисляет тестовый коэффициент и печатает его **первой строкой**. Ни веб-сервер, ни база SQLite для этого не нужны. Это снимок текущих данных: число может измениться при следующем запуске и **не заменяет суточный коэффициент**. Нужен доступ к интернету; если один из обязательных источников недоступен, скрипт сообщает об ошибке вместо вымышленного числа.

### Круглосуточный сервер

```sh
python timelinestamp.py
```

Откройте на том же устройстве [http://127.0.0.1:8765](http://127.0.0.1:8765). В рабочем каталоге с соседней папкой `local/` база SQLite создаётся в `../local/data/timelinestamp.sqlite3`; при отдельной установке — в `data/timelinestamp.sqlite3`. Адрес, порт и путь можно изменить флагами `--host`, `--port`, `--db`. По умолчанию интерфейс доступен только на самом устройстве; при `--host 0.0.0.0` он становится доступен в локальной сети **без авторизации**.

### Выделенный Android-телефон

Подготовлены запуск без локального веб-сервера, автоматический старт через Termux:Boot, повторный запуск после сбоя, ограниченный по размеру журнал, две сменяемые сжатые копии полной базы, доступ по SSH в локальной сети по ключу и публикация небольшого снимка в GitHub Pages. Старые измерения не удаляются. Пошаговая установка и настройка SSH — в [ANDROID.md](ANDROID.md). Пока репозиторий GitHub не создан, телефон может собирать данные локально без токена.

```sh
python timelinestamp.py --headless
python timelinestamp.py --status
```

Техническая версия сайта лежит в `docs/`; новый дизайн с тремя языками собирается командой `python3 demo/build.py` в соседнюю локальную папку `../local/TimeLineStamp-demo.html`. Перед публикацией новый дизайн нужно связать с настоящими данными. Настройка будущей публикации описана в [GITHUB_PAGES.md](GITHUB_PAGES.md). GitHub получит только итог, историю за 30 дней и счётчики источников; сырые ответы и SQLite останутся на телефоне. Никакая страница проекта пока не опубликована.

Исходники для Git находятся только в этой папке. Локальная база, превью дизайна и заметки хранятся в соседней папке `../local/`, которая не входит в репозиторий. Для коммитов используйте псевдоним проекта, адрес GitHub `noreply` и UTC; локальные проверки Git блокируют неподходящую личность и личные идентификаторы в изменениях.

## Правило расчёта v1

- Период измерений: календарные сутки UTC, `00:00:00`–`23:59:59`.
- Квантовые маяки: пульсы для минут `00, 05, 10, …, 55` каждого часа, то есть по 288 ожидаемых пульсов в сутки на источник. Запрос начинается после публикации пульса; неудачный запрос повторяется до десяти минут. Старые периоды не заполняются задним числом.
- NOAA: файлы `rtsw_mag_1m.json` и `rtsw_wind_1m.json` опрашиваются примерно раз в час. Сохраняются первые полученные записи с `active=true`, `overall_quality=0` и числовыми измерениями. Время и название аппарата берутся из ответа NOAA. Доступные записи можно подобрать из опубликованного файла за последние сутки до суточной фиксации.
- Первый неполный день после установки исключается. Первый отпечаток появится в `00:15 UTC` после первого **полного** дня сбора.
- В `00:15 UTC` каждый завершённый день получает каноническую запись с фиксированным порядком источников, всеми ожидаемыми квантовыми слотами и явными `null` для пропусков. Состав записи описан в `Store.finalize_day`.
- `SHA-256` этой записи — полный отпечаток. Коэффициент `1.xxxxxx` получается из него детерминированно с устранением смещения при переводе в миллион вариантов. Он никогда не пересчитывается после записи в таблицу `days`.
- Если за сутки нет ни одного квантового пульса, полный хеш сохраняется, а коэффициент не выдаётся. При существенных пропусках коэффициент показывается с пометкой «неполные данные».

Исходные ответы маяков, выбранные строки NOAA, адрес запросов, время получения и хеш HTTP-ответа сохраняются в SQLite. **Криптографические подписи маяков в v1 пока не проверяются программой**; их поля сохраняются для последующей проверки. HTTPS, проверка времени пульса, индекса и обычного статуса маяка используются при приёме данных. Публичные API и формат могут измениться, поэтому при обновлении источника понадобится новая версия правила расчёта, а старые дни должны оставаться неизменными.

## API интерфейса

- `/api/status` — текущая зафиксированная запись, последние 30 дней и ход сегодняшнего сбора.
- `/api/day/YYYY-MM-DD` — полный SHA-256, коэффициент, качество и числа принятых измерений за день.
- `/api/day/YYYY-MM-DD/manifest` — канонические входные данные за день, из которых пересчитывается полный отпечаток.

Интерфейс не отправляет данные третьим лицам. Сами измерения запрашиваются телефоном у NIST, NQSN и NOAA.

## Источники

- [NIST Beacon API](https://csrc.nist.gov/Projects/interoperable-randomness-beacons/beacon-20)
- [NQSN Beacon API](https://quantum-entropy.sg/api/beacon/)
- [NOAA SWPC Solar Wind](https://swpc-drupal.woc.noaa.gov/products/solar-wind)

Потоки данных принадлежат соответствующим операторам. NQSN помечает своё программное обеспечение как находящееся в испытательной стадии; устойчивость и статус источника нужно наблюдать во время эксплуатации.
